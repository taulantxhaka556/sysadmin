# Network Exam — Vercel

Платформа подготовки к экзамену: 60 вопросов, 40 практических заданий, 10 этапов,
тренажёр IPv4, пробный экзамен и журнал оценок 0–100.

## Интерактивный курс — 14 модулей

- `/learn/1` — начало курса с сохранением в PostgreSQL. Модули 1–14 открываются последовательно после практической модели и теста от 70/100; преподаватель может просматривать все.
- `/learn/1/demo` — публичная демонстрация с выбором любого модуля. Демо хранится отдельно в БД, в подписанной cookie только случайный идентификатор. Очистка после 14 дней бездействия при создании новой демосессии.
- Все 60 исходных тем: короткая теория, 180 заданий с объяснениями и подсказками; 14 практических моделей и итоговые тесты. Малые модули содержат минимум 3 экзаменационных задания.
- Модели: топология, Ethernet, IPv4, VLAN/trunk, OSPF и маршруты, DHCP/DNS, PAT, Wi-Fi, ВМ, диагностический терминал, ACL, TLS/VPN, облачные права и итоговая сеть. Это ограниченные учебные модели без выполнения реальных команд.
- Все 40 исходных практических работ связаны с модулями и открывают действующую форму отчёта. Автоматический результат модели не заменяет отчёт и оценку преподавателя.
- Сервер проверяет ответы, последовательность, CSRF и срок теста (10–15 минут). После истечения времени — 0; повторные попытки и разбор доступны. Подсказка снижает балл задания до 95.
- Индивидуальный журнал показывает все 14 модулей: уроки, проверки, практику и лучший тест. Прежние ручные оценки 10 этапов сохранены отдельно.
- `course_catalog.py` — покрытие исходных 100 заданий; `course_lessons.py` — уроки 2–14; `module1_content.py` — первый модуль; `course_labs.py` — модели; `learning.py` — API и прогресс; `static/learn.*`, `static/course-ui.js` — интерфейс.
- При развёртывании `python init_db.py` добавляет таблицы прогресса без удаления прежних аккаунтов, работ и оценок. Таблица первого модуля сохраняется.

## Учебный процесс

1. Преподаватель создаёт группы в /admin.
2. Студент регистрируется, выбирает группу и изучает этапы в /dashboard.
3. По теории сдаёт письменный ответ; по практике — отчёт и при необходимости файл.
4. Преподаватель оценивает или возвращает работу с комментарием.
5. /journal показывает матрицу работ по группе и этапу. Нажмите на имя студента,
   чтобы выставить итог каждого этапа. Итог выставляется вручную, отдельно от среднего балла.
6. Студент видит только свои оценки и комментарии.

Есть CSV-экспорт, аналитика, история оценок и редактор материалов. После отправки работу
нельзя менять до возврата на доработку. Все оценки 0–100. Packet Tracer и свободные ответы
проверяются вручную. Конспекты вводные, сгруппированы по этапам и доступны для редактирования.
Для VPN и отдельных служб нужна совместимая модель симулятора или лабораторная ВМ.

## Локальный запуск (PowerShell, Python 3.12)

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
$env:ADMIN_EMAIL="teacher@example.com"
$env:ADMIN_PASSWORD="your-unique-password-at-least-12-chars"
$env:SESSION_SECRET="your-random-secret-at-least-32-chars"
.\.venv\Scripts\python -m uvicorn main:app --reload
```

Откройте http://127.0.0.1:8000. Локальная база — local.db, файлы — uploads.
.env.example является примером: приложение автоматически не читает .env.

## Vercel

FastAPI поддерживается напрямую; точка входа main.py:app. vercel.json запускает
python init_db.py при сборке. Output Directory задавать не нужно.

1. Импортируйте репозиторий GitHub в Vercel.
2. Подключите PostgreSQL через Marketplace (например Neon). Задайте DATABASE_URL
   с pooled URL и TLS. Также поддерживается POSTGRES_URL. SQLite на Vercel запрещён.
3. Подключите **Private Vercel Blob**. Нужен BLOB_READ_WRITE_TOKEN либо подключённый
   store с BLOB_STORE_ID и OIDC. Публичное хранилище не подходит для работ студентов.
4. Задайте переменные окружения до сборки:

| Переменная | Назначение |
|---|---|
| DATABASE_URL | PostgreSQL URL с TLS |
| SESSION_SECRET | Случайная строка от 32 символов |
| ADMIN_EMAIL | Email преподавателя |
| ADMIN_PASSWORD | Пароль от 12 символов для первого создания администратора |
| BLOB_READ_WRITE_TOKEN | Токен Private Blob, если не используется OIDC |

5. Выполните Deploy. Сборка создаст таблицы, задания и администратора. PostgreSQL advisory
   lock защищает от одновременной инициализации. Повторная сборка сохраняет данные,
   существующие пароли и учебные материалы.
6. Проверьте /health, создайте группу, зарегистрируйте тестового студента, отправьте
   работу, скачайте её преподавателем и выставьте оценку.
7. Используйте разные базы и Blob для Preview и Production. Включите резервные копии БД.

Не сохраняйте секреты, базы и работы студентов в GitHub. Для публикации нужен доступ к Vercel.
Изменение ADMIN_PASSWORD не меняет пароль уже существующего пользователя.

### Файлы

Лимит файла — **4 МиБ**, с запасом до лимита запроса Vercel 4,5 МБ.
Форматы: pkt, pka, png, jpg, jpeg, pdf, txt, zip, pcap, pcapng.
Скачивание закрытых файлов проходит через проверку владельца/преподавателя.
Ссылки и токены Blob не раскрываются. Файлы не исполняются и не распаковываются.
Большие файлы потребуют отдельной прямой загрузки в Blob.

Перенос старой установки требует отдельного переноса SQLite в PostgreSQL и uploads в Blob
с обновлением ссылок. Push кода не переносит пользовательские данные автоматически.

## Проверки

```powershell
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m pytest -q
```

Тесты используют отдельную временную базу. Проверяются сдача, доработка, журнал,
ограничения доступа, CSRF, повторная инициализация и контракт закрытого Blob с подменённым SDK.
Настоящие PostgreSQL и Blob нужно проверить после подключения облачных ресурсов.

## Ограничения

Нет подтверждения email/группы, восстановления пароля, антивирусной проверки вложений
и системы миграций существующих таблиц. Перед публичным использованием настройте
ограничения частоты входов и регистраций в Vercel Firewall. История сохраняет оценки
и комментарии; полный архив версий файлов пока не ведётся.
